# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# First-time setup
bundle install
npm install

# Development (Jekyll + Tailwind in watch mode)
npm run dev

# Or separately in two terminals:
bundle exec jekyll serve --livereload
npm run css:watch

# Production build
npm run build
```

`assets/css/main.css` is generated by Tailwind and gitignored — it must be built before Jekyll can serve the site.

## Architecture

Jekyll 4 static site · Tailwind CSS 4 · Alpine.js 3 (CDN) · German only

For a C4 Context+Container diagram and more detail on deploy/CI, see [`docs/architecture.md`](docs/architecture.md). For the ongoing agent-automation rollout (Jira integration, PR-gated agent loop, etc.), see [`docs/automation-plan.md`](docs/automation-plan.md).

### Deploy

Two deploy pipelines run on every push to `main`:
- **Azure Static Web Apps** (`.github/workflows/azure-static-web-apps-brave-smoke-037a8b003.yml`) — canonical deploy target (decided 2026-07-23).
- **GitHub Pages** — legacy, runs in parallel. It cannot be disabled via API/settings because this repo is named `carofuerhunde.github.io` (org/user Pages repo); GitHub refuses deactivation (`422`). Treat Azure as canonical in docs only — both hosts stay live technically.

### eTermin (booking system)
Appointments, calendars, absences, services etc. are managed via the eTermin API using `scripts/etermin.js` (`node scripts/etermin.js GET calendar`). Credentials live in gitignored `.env.etermin`. Writes are dry-run unless `--yes` — always confirm with the user before sending one. Details and resource list: [`docs/etermin.md`](docs/etermin.md).

### Jira — single point for tasks

All tasks and requirements live in **one** Jira project: **`CARO`** ("Caro Hundeschule") on `https://martinalter-itconsulting.atlassian.net` (Cloud ID `9095a019-7ae4-4a5e-a3f8-8b536fe8bf56`). Board: <https://martinalter-itconsulting.atlassian.net/jira/software/projects/CARO/boards/2/backlog>.

- Jira is the only source for tasks — not GitHub Issues, not Confluence. Look for work in `CARO`, and file new work there.
- Access is via the Atlassian MCP connector (`mcp__claude_ai_Atlassian_Rovo__*`). Pass the site hostname `martinalter-itconsulting.atlassian.net` as `cloudId`. The connector also knows `communardo.atlassian.net` — do not use that site for this project.
- The project was recreated in 2026-10; the old `CARO-*` tickets and the former `HUN` project no longer exist. Old branch names like `CARO-11` or `HUN-5` have no matching ticket.

### Branch naming convention

Ticket → branch (`CARO-<number>`) → PR referencing the ticket. This is the intended hook for the future agent automation described in `docs/automation-plan.md` (Milestone M2+): an agent will read a Jira ticket, implement on a matching branch, and open a PR linking back to it.

### Content data (`_data/`)
All content that repeats across pages lives here:
- `navigation.yml` — main nav links (header + footer)
- `services.yml` — 6 service cards with `slug`, `icon`, `short`, `details` (details rendered via `| markdownify`)
- `team.yml` — team member profiles
- `welpen.yml` — puppy directory (sorted A–Z in `welpen.html`)

### Layouts & includes
- `_layouts/default.html` — base layout; loads Inter font, Tailwind CSS, Alpine.js CDN, jekyll-seo-tag
- `_layouts/page.html` — simple content page with page-hero header section (extends default)
- `_includes/header.html` — sticky header with Alpine.js mobile menu (`x-data="{ open: false }"`)
- `_includes/footer.html` — dark footer with service list from `_data/services.yml`
